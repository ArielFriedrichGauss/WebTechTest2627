# Reviewer notes (USThing members only)

This starter is meant to remove setup tax, not the evaluation surface.

## Intentionally provided

- Next.js + TypeScript + Tailwind
- Dashboard-aligned colour tokens, Poppins, simplified sidebar
- Type suggestions and **three** sample venues / **two** sample reviews
- An empty home canvas and a stub `/venues/[id]` route
- Applicant README with requirements, a suggested week plan, and feasibility guardrails

## Intentionally not provided

- A working discovery, filter, sort, or map experience
- A real venue catalogue
- Comparison UI
- Review create/edit flows
- Favorites, “open now”, or any extra feature
- Component library for food cards

## What to judge

Use the public grading criteria in the README. In practice:

| Strong | Weak |
| --- | --- |
| Local HKUST food knowledge, even if mock | Generic restaurants that could be anywhere |
| Students can decide in a few seconds | Feature list without a decision path |
| Extra features that could ship later | Seating sensors, live kitchen cameras, payments |
| Commits tell a story | One dump commit, or AI-generated wall of files with no authorship |
| Looks like USThing | Unrelated visual language, or an untouched starter page |

If the applicant discarded the starter and rebuilt from scratch, that is allowed. Still expect USThing visual language and the minimum product requirements.
